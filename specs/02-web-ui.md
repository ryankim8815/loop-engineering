# 02. 웹 UI

## 개요

- 서버가 `public/` 디렉터리를 정적으로 제공하며 `GET /`는 `public/index.html`을 반환한다.
- 프레임워크·번들러 없이 **바닐라 HTML/CSS/JavaScript(ES Modules)** 로 작성한다.
- UI는 오직 [01-todo-api.md](01-todo-api.md)의 API만 사용한다.

## 화면 구성

1. 상단: 제목 입력창 + "추가" 버튼
2. 중앙: Todo 목록. 각 항목은 체크박스 · 제목 · 삭제 버튼
3. 하단: 남은(미완료) 개수 · 필터(전체/진행 중/완료) · "완료 항목 삭제" 버튼

## 동작

| 사용자 행동 | 결과 |
| --- | --- |
| 입력창에 제목 입력 후 Enter 또는 "추가" | 목록 맨 아래에 추가되고 입력창이 비워진다 |
| 빈 제목으로 추가 시도 | 요청을 보내지 않고 입력창 근처에 안내 문구를 표시한다 |
| 체크박스 토글 | 완료 상태가 바뀌고 완료 항목은 취소선으로 표시된다 |
| 제목 더블클릭 | 인라인 편집. Enter=저장, Esc=취소, 빈 값으로 저장 시 취소, 포커스를 잃으면(blur) 취소 |
| 삭제 버튼 | 해당 항목이 사라진다 |
| 필터 클릭 | 해당 상태의 항목만 표시. 선택된 필터를 시각적으로 구분하고 URL 해시(`#/active` 등)에 반영 |
| API 오류 | 화면 상단에 오류 메시지를 표시하고 화면 상태를 서버와 다시 맞춘다 |

## 접근성·반응형

- 모든 컨트롤은 키보드만으로 조작 가능하고 `label` 또는 `aria-label`이 있다.
- 폭 360px 모바일 화면에서 가로 스크롤이 생기지 않는다.

## 수용 기준 (Acceptance Criteria)

- [ ] AC-UI-1: `GET /`는 200과 `text/html`을 반환하고 입력창·목록·필터 요소를 포함한다.
- [ ] AC-UI-2: `public/` 아래의 JS 모듈이 `text/javascript`(또는 `application/javascript`)로 제공된다.
- [ ] AC-UI-3: UI의 상태 로직(필터링·남은 개수 계산·입력 검증)은 DOM과 분리된 순수 함수로 작성되고 단위 테스트가 있다.

아래 기준은 `happy-dom` 환경에서 `public/index.html`과 UI 모듈을 불러오고, `fetch`를 가짜(stub)로 바꿔 DOM 테스트로 검증한다([03-tech-stack.md](03-tech-stack.md) 참고).

- [ ] AC-UI-4: 제목 입력 후 Enter를 누르면 `POST` 요청이 가고, 목록 맨 아래에 항목이 추가되며, 입력창이 비워진다. 빈 제목으로 Enter를 누르면 요청 없이 안내 문구가 보인다.
- [ ] AC-UI-5: 체크박스를 토글하면 `PATCH`가 가고 완료 표시가 바뀐다. 삭제 버튼을 누르면 `DELETE`가 가고 항목이 사라진다. 남은 개수 표시가 갱신된다.
- [ ] AC-UI-6: 필터를 클릭하면 URL 해시가 `#/active` 등으로 바뀌고 해당 항목만 보인다. 페이지를 해시 `#/completed`로 열면 처음부터 완료 필터가 적용된다.
- [ ] AC-UI-7: 제목을 더블클릭하면 편집 입력창이 나타난다. Enter는 `PATCH`로 저장하고, Esc·빈 값·포커스 이탈(blur)은 요청 없이 원래 제목으로 되돌린다.
- [ ] AC-UI-8: API가 오류를 반환하면 오류 배너(`role="alert"`)에 메시지가 보이고, 목록을 다시 불러와 서버 상태와 맞춘다.
